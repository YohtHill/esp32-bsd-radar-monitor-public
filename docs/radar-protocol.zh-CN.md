# 从雷达串口帧到安卓界面

[English](radar-protocol.md) · [项目首页](../README.zh-CN.md) · [固件设计](design.zh-CN.md)

## 两条串口的职责

USB 串口使用 **115200 baud**，用于看日志和输入调试命令。雷达通过 **UART2 921600 baud，8N1** 与 ESP32 相连。雷达 TX 接 GPIO16，雷达 RX 接 GPIO17。启动阶段，程序每 1500 ms 轮换发送版本查询 `FE`、感知状态查询 `D0` 和开启感知 `D1`。收到校验通过的应答或上报后，停止周期探测。若还需启动感知，应答处理函数会继续尝试 `D1`。协议锁定表示收到了有效封装，目标更新还要等有效的 BSD 上报。[初始化与探测源码](../src/main.cpp#L1070-L1160)

| 帧头 | 方向 | 当前实现 |
| --- | --- | --- |
| `0x58` | ESP32 → 雷达 | 命令、参数长度、参数和 16 位小端累加校验 |
| `0x59` | 雷达 → ESP32 | 应答命令、参数长度、参数和 16 位小端累加校验 |
| `0x5A` | 雷达 → ESP32 | 载荷长度、载荷和 8 位累加校验。`TYPE 0x07` 载荷用于 BSD 目标 |

## 接收时为何先查长度再查校验

ESP32 将收到的字节逐个放入 256 字节接收缓冲区。它跳过不以 `0x59` 或 `0x5A` 开头的字节，等待长度字段指定的完整候选帧。候选帧超长或校验失败时，从候选起点丢掉一个字节继续找帧头。通过校验的上报还需检查 `TYPE`、目标数量及目标字段的最小长度。这个过程允许 UART 将一帧拆成多次到达，或连续送来多个帧。 [缓冲、重同步和校验实现](../src/main.cpp#L1732-L1812)

~~~mermaid
flowchart TD
    A["UART2 字节进入接收缓冲"] --> B["找 0x59 或 0x5A 帧头"]
    B --> C{"按长度收齐候选帧？"}
    C -->|等待余下字节| A
    C -->|是| D{"累加校验通过？"}
    D -->|否，丢候选起始字节| B
    D -->|是| E{"帧类型"}
    E -->|0x59| F["处理命令应答"]
    E -->|0x5A 和 TYPE 0x07| G["读取目标数、检查最小长度、逐目标解码"]
    G --> H["0 个目标时清空，有目标时写入最新帧"]
~~~

## 把答辩中的实测帧拆开

~~~text
5A 09 07 01 00 00 00 02 37 00 00 A4
~~~

| 字节偏移 | 数据 | 解读 |
| ---: | --- | --- |
| 0 | `5A` | 主动上报帧头 |
| 1 | `09` | 载荷长 9 字节，整帧共 12 字节 |
| 2 | `07` | BSD 上报类型 |
| 3–4 | `01 00` | 小端 16 位目标数，等于 1 |
| 5–6 | `00 00` | 目标数后的保留字段，当前解析跳过 |
| 7 | `02` | 距离 2 米 |
| 8 | `37` | 方位 +55°，按当前软件分到右侧 |
| 9 | `00` | 径向速度 0 米/秒 |
| 10 | `00` | 目标 ID 0 |
| 11 | `A4` | 前 11 个字节求和取低 8 位，结果为 0xA4 |

每个 BSD 目标占四字节，顺序为距离、角度、速度、ID。距离、角度、速度由固件按有符号 8 位解析，单位依次为米、度、米/秒。目标 ID 在当前代码中存为字节值。载荷最短长度为 `1 + 4 + 4 × N`，最多接收 8 个目标。当前代码拒绝短帧和超出目标上限的帧，容许比最小长度更长的载荷。[BSD 目标解析源码](../src/main.cpp#L1604-L1635)

例如，如果速度字节为 `FE`，有符号值为 −2 米/秒。ESP32 向 App 发送时乘以 3.6，得到 −7.2 km/h。负值表示靠近是本项目当前安装和代码采用的约定。换安装方向要先用已知方向的移动目标复核符号。

## 安卓如何收到并显示目标

Android 与 `ESP32_BSD_MONITOR` 建立经典蓝牙 RFCOMM/SPP 连接，在后台线程按换行读状态。ESP32 发送逗号分隔的 `键:值` 字段。摘要描述主目标和全局状态，`T0_` 到 `T7_` 描述逐目标列表。每个有效新帧可以触发即时上报，连接后还有约 250 ms 的周期发送；周期参数无法代表测得的端到端延迟。

| 字段 | 作用 |
| --- | --- |
| `STATE`、`RISK`、`LEVEL` | 系统状态、融合风险、界面风险等级 |
| `ZONE`、`DIST`、`SPEED`、`ANGLE`、`ID` | 主目标的方向与测量值 |
| `CNT`、`T{n}_ID`、`T{n}_ZONE`、`T{n}_DIST`、`T{n}_SPEED`、`T{n}_ANGLE`、`T{n}_LEVEL` | 目标总数和逐目标记录 |
| `COLLISION`、`C_COUNT`、`BUZZER` | 机械触发状态、累计计数与蜂鸣器状态 |
| `MSG` | 碰撞确认、报警或误报处置提示，在相应状态下发送 |

安卓解析这些字段来刷新扇区图、风险颜色和目标表。手机向 ESP32 发一条换行结尾的 `MUTE`、`ALARM`、`FALSE` 或 `RESET`。固件还允许通过 USB 串口输入同样的命令，方便在没有手机时验证处置逻辑。[ESP32 状态编码](../src/main.cpp#L922-L1004) · [安卓读取线程与界面更新](../android_app/app/src/main/java/com/example/bsdmonitor/MainActivity.java#L622-L715)
