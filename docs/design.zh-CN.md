## 雷达实际测量什么

MS60-1211S80M-BSD 是课程使用的 60 GHz FMCW 模块。模块发射一组扫频信号。回波延时导致的拍频用于估计距离，连续 chirp 的相位变化用于估计径向速度，接收通道之间的相位关系用于估计角度。答辩记录使用 1 发 4 收的描述。项目没有拿到天线阵列几何、原始采样或点云，因此在 ESP32 上直接消费目标报告。

| 参数 | 模块手册给出的口径 | 项目如何使用 |
| --- | --- | --- |
| 频段与带宽 | 59–64 GHz，2 GHz 可调带宽 | 作为传感器背景。ESP32 处理目标上报。 |
| 标称视角 | 水平与俯仰各 ±60° | 固件只用水平角做分区。装车偏角和遮挡需要实测。 |
| 标称探测距离 | 汽车 0.5–40 米，摩托车 0.5–30 米，自行车 0.5–20 米，行人 0.5–15 米 | 范围取自模块资料。原型尚无按目标类型测得的距离上限。 |
| 更新和建立探测 | 手册列出 100 ms 刷新、5 s 建立探测 | 和 ESP32/安卓的刷新周期不同，不能直接换算为实测端到端延迟。 |

资料里的视角、报告中用于说明场景的扇区示意和代码中的分区边界，分别回答模块标称覆盖、场景示意和软件归类。当前代码把 **−60° 至小于 −15°** 判为左、**−15° 至 +15°** 判为中、**大于 +15° 至 +60°** 判为右，其余标为无分区。分区只是目标角度的类别，尚未测定装车后的有效波束范围。[分区函数](../src/main.cpp#L320-L337)

## ESP32 怎样跑整个循环

程序保留最近一帧 `RadarFrame` 与接收时间，一帧可包含最多八个 `RadarTarget`。在循环中采样振动输入、读 USB 和蓝牙命令、接收雷达字节，再更新状态、蜂鸣器和显示。新 BSD 帧也可立即触发界面和蓝牙更新。[主循环](../src/main.cpp#L1901-L1922)

| 节奏 | 作用 |
| --- | --- |
| 25 ms 去抖、3 s 近期碰撞标志 | 振动输入在稳定激活沿加一次计数。状态的人工确认可以长于 3 s。 |
| 2 s 雷达数据有效期 | 非零目标帧以接收时间判断新鲜度。有效零目标帧会主动清空。 |
| OLED 250 ms，目标页 1200 ms | 每页最多显示四个目标。 |
| TFT 1000 ms，蓝牙 250 ms | 定时刷新与上报。部分事件可以强制刷新，参数为设计节奏。 |
| 5 s 串口链路日志 | 查看累计入字节、校验通过帧和丢弃字节。 |

## 如何从距离和速度决定风险

机械振动输入有最高优先级。没有机械触发时，固件以径向速度为接近判据，当前安装约定负值为靠近。以下规则自上往下匹配。[融合规则与目标选择](../src/main.cpp#L198-L258)

| 优先条件 | 融合风险 |
| --- | --- |
| 振动仍有效，或处于近期碰撞时段 | `HIT` |
| 无目标 | `OK` |
| 目标在 4 米以内，含 4 米 | `NEAR`。先按近场反射下读数可能不稳定处理。 |
| 目标在 4 到 8 米之间且以至少 1 米/秒靠近，或在 4 米外以至少 2 米/秒靠近 | `WARN`。8 米纳入第一项。 |
| 前面未匹配，距离不超过 8 米或以至少 1 米/秒靠近 | `NEAR` |
| 其他目标 | `TRACK` |

逐目标评估后，摘要选风险最高者。同级取更近者。在答辩的双目标画面中，**中间目标 4 米、−3.6 km/h** 对应 −1 米/秒，落在近场规则。**左侧目标 10 米、−7.2 km/h** 对应 −2 米/秒，达到快速靠近规则，因此更远的左侧目标也可以先显示预警。

融合风险、顶层状态和界面条形等级各有作用。`WARNING` 表示此时有有效目标，`WARN` 才是雷达蜂鸣的风险条件。逐目标 `LEVEL` 还和近距离分档取较高值，界面显示 5 不等于检测到机械碰撞。碰撞确认或本地报警会把摘要等级设为 5。[界面等级计算](../src/main.cpp#L588-L635)

## 人工确认与恢复

~~~mermaid
flowchart LR
    S["SAFE 正常监测"] -->|收到有效目标| W["WARNING 有目标"]
    W -->|目标清空或过期| S
    S -->|机械振动去抖通过| C["COLLISION_CONFIRM 待确认"]
    W -->|机械振动去抖通过| C
    C -->|ALARM| A["ALARMING 本地报警"]
    C -->|FALSE| F["FALSE_ALARM 误报"]
    F -->|2 秒后| N["按最新目标选择监测状态"]
    C -->|RESET| N
    A -->|RESET| N
    N -->|无有效目标| S
    N -->|有有效目标| W
~~~

图中给出主要处置路径。指令处理函数也允许在其他状态接收 ALARM、FALSE、MUTE 和 RESET。

| 状态或操作 | 当前固件行为 |
| --- | --- |
| `SAFE` / `WARNING` | 常规监测按是否有有效目标切换。目标超时后，常规监测可回到 `SAFE`。 |
| `COLLISION_CONFIRM` | 稳定机械触发进入确认，计数加一。近期碰撞标志到期后仍可停留在确认状态，等待指令。 |
| `ALARM` | 进入 `ALARMING`，关闭当前蜂鸣器并发送 App 状态。在当前实现中这是本地提示。 |
| `FALSE` | 进入 `FALSE_ALARM`，清除近期碰撞计时并静音。2 秒后按目标是否有效恢复 `SAFE` 或 `WARNING`。 |
| `MUTE` | 关闭当前蜂鸣，系统状态保持。切换状态时会清除静音标志。 |
| `RESET` | 清除近期碰撞计时和静音，按最新目标恢复监测。累计碰撞计数保留。 |

没有静音时，`WARNING` 加 `WARN` 的蜂鸣翻转间隔是 500 ms，碰撞确认时为 100 ms。OLED 的安全布尔值依据是否存在有效目标和振动输入，安卓还会显示系统态与提示字。因此不同显示面需要按各字段含义解读。[状态与蜂鸣器](../src/main.cpp#L356-L423) · [处置指令](../src/main.cpp#L1299-L1350)
